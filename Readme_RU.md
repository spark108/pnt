# PNT

[English](README.md) · [Клиент PNT VPN](https://github.com/spark108/amnezia-pnt)

PNT — служба на .NET 10 для доверенного децентрализованного кластера серверов Debian и Windows. Она предоставляет удалённые команды с маршрутизацией, TCP-пробросы, мониторинг, веб-глобус и управляемый доступ к AmneziaWG. Каждый узел хранит собственную SQLite-базу и постоянный сертификат. Зашифрованные соединения и поиск маршрутов работают фоном, включая обратные подключения узлов за NAT.

## Установка и обновление

На Debian 12 или 13, из каталога исходников:

```sh
git clone https://github.com/spark108/pnt.git
cd pnt
sudo ./pnt.sh install
sudo ./pnt.sh start
sudo ./pnt.sh stop
sudo ./pnt.sh restart
./pnt.sh status
sudo ./pnt.sh update
```

Установщик подготавливает .NET 10 SDK, libmsquic, Git, SSH, PTY и средства брандмауэра, собирает автономный бинарник и запускает `pnt.service`. Не удаляйте исходники: установленная команда управления использует этот скрипт. Если выбран неверный адрес, задайте `PNT_ADVERTISE_IP` в `/etc/default/pnt` и перезапустите службу до вступления или создания кластера.

На Windows откройте исходники в терминале администратора:

```bat
pnt.bat install
pnt.bat update
pnt.bat start
pnt.bat stop
pnt.bat restart
pnt.bat status
```

Установщик подготавливает Git/.NET, регистрирует автоматическую службу `PNT` от LocalSystem и добавляет `pnt.cmd` в системный PATH. Затем откройте новый терминал. `npt.bat` — совместимое имя скрипта. При ошибках прав SQLite в старой установке обновите исходники и выполните `pnt.bat repair` от администратора; данные и идентичность сохраняются.

Установленный CLI также поддерживает `pnt install`, `pnt update` и `pnt update --check`. Установка/обновление выполняются фоновым процессом с журналом и текущим этапом в терминале; закрытие просмотра не отменяет работу. Сначала обновляются исходники, затем запускается новый установщик, устанавливаются его зависимости, собирается программа и перезапускается служба. При сбое установки выполняется попытка восстановления.

Ручное обновление объявляет событие кластеру, даже если коммит уже установлен. Остальные узлы применяют его без зацикливания; отключённые получают событие после восстановления связи. Обновляющиеся узлы показывают `update`. Старым установкам нужно первое локальное обновление для получения этого механизма.

### Удалённая установка на Debian

```sh
pnt install -r root@192.0.2.20
# Альтернатива через скрипт:
sudo ./pnt.sh install -r root@192.0.2.20
```

PNT выбирает доступный Linux-узел с SSH-доступом к серверу и возвращает запросы ввода/журнал по маршрутам кластера. После SSH-авторизации установщик регистрирует новый узел и передаёт ключ подключения, параметры кластера и закреплённый сертификат входного узла через стандартный ввод SSH. Заявка, ожидание подтверждения и ручное принятие не нужны; служба автоматически устанавливает исходящее соединение с кластером. Ключ не попадает в аргументы команд и журналы установки. Участие в существующем кластере не перезаписывается. При необходимости SSH-авторизация запрашивается интерактивно; PNT не сохраняет пароли. Windows-серверы устанавливаются локально.

## Управление кластером

```sh
# Первый участник:
pnt node init 'replace-with-your-cluster-key'
pnt node name edge-1
# Новый участник с работающей службой:
pnt node identity --fingerprint
pnt node join 192.0.2.10
pnt node status
# Действующий участник:
pnt node requests
pnt node accept <new-node-id>
pnt node reject <new-node-id>

pnt node list
pnt node list <source-node>
pnt node list --interactive
pnt node routes [node]
pnt node relay enable [node]
pnt node relay disable [node]
pnt node relay status [node]
pnt node kick <node>
pnt node remove <node>
pnt node leave
pnt node <id> reboot
pnt node <id> reboot -f
```

До подтверждения проверьте идентичности и сертификаты. Начальное соединение использует доверие при первом обращении: сравните закреплённый сертификат из `node status` по доверенному каналу. Ожидающие заявки истекают через десять минут. Приглашения доступны через `pnt node invite`.

Узлу за NAT нужен исходящий доступ к известному участнику, без входящего проброса порта. Публичного сервера обнаружения и UDP hole punching нет. Подтверждённые прямые пути приоритетны; для альтернатив учитываются транзит через NAT, задержка и стабильность.

Задержка между узлами измеряется короткими запросами PNT, без ICMP; реле указываются. `node list <source-node>` показывает измерения указанного узла. `--interactive` обновляет таблицу до Ctrl+C. `kick` запрашивает добровольный выход и распространяет удаление после подтверждения; `remove` исключает без ответа целевого узла. Перезагрузка всей ОС выполняется через пять секунд: для одного узла нужен ввод его ID; `-f` означает принудительную перезагрузку и не отменяет подтверждение.

По умолчанию у всех нод, включая существующие, обычный транзит включён. `node relay disable [node]` переводит узел в **резервное реле**: новые маршруты используют его как промежуточный только при отсутствии рабочего пути через обычные реле. Исходящие команды и обращения к самой ноде остаются доступны. Без `[node]` выбирается текущая нода; `*` позволяет массовую настройку с подтверждением. Режим сохраняется и распространяется по кластеру. Обычные реле предпочитаются даже при меньшем пинге через резервное. Перед резервом выполняется поиск обычного пути; после восстановления он снова получает приоритет. Служебный поиск и синхронизация продолжаются: это приоритет маршрутизации, а не запрет сетевых соединений. Открытые потоки не разрываются. В `node list` есть столбец реле, в `node routes` отмечен резервный транзит. Обновите всех участников: старые версии не учитывают эту настройку.

## Удалённые команды

```sh
pnt sh <node> 'hostname'
pnt sh <linux-node> --interactive bash
pnt sh <windows-node> --interactive cmd
pnt ping example.com
```

Маршрут подтверждается до отправки задачи. Вывод поступает в реальном времени. Если после отправки результат неизвестен, команда автоматически не повторяется. Linux использует `/bin/sh -c`, Windows — `cmd.exe /d /s /c`, от имени службы.

Для терминального режима обновите CLI и целевые узлы. Интерактивные сеансы используют Linux PTY / [Windows ConPTY](https://learn.microsoft.com/en-us/windows/console/creating-a-pseudoconsole-session). Стрелки, Home/End, редактирование и историю обрабатывает удалённая оболочка; ANSI-цвета сохраняются. Сочетания зависят от оболочки. Нужны терминал без перенаправления и один явно выбранный узел. Linux-сеансы по умолчанию хранят историю в памяти, без записи файла истории.

`pnt ping <IPv4/domain>` отдельно измеряет внешний ICMP-пинг с доступных участников и показывает лучший выход и пути обращения к узлам.

## Селекторы: все, списки и исключения

В Unix-оболочке заключайте `*` в кавычки, чтобы она не подставила имена файлов:

```sh
pnt vpn client allow '*' node-name
pnt vpn client allow '*' '*'
pnt vpn client allow '*,-<client_id>' '*'
pnt vpn client allow '<client_id>,<client2_id>' '*,-<node_id>,-<node2_id>'
pnt vpn client create NewClient --servers '*' --out=/tratsuk.pnt
pnt vpn client deny '*' node-name
pnt vpn client unbind '*'
pnt sh '*' 'hostname'
pnt node '*' reboot
```

Запятая объединяет явно указанные ID/имена, `*` выбирает доступный набор, `-id` исключает объект после объединения всех положительных элементов. Порядок исключений не важен, дубликаты убираются. Нужны `*` или хотя бы один положительный элемент; только исключения, неизвестные объекты и пустой результат отклоняются до изменений. Синтаксис работает и в `--servers`, например `--servers '*,-node-id'`. Списки и исключения также требуют подтверждения.

PNT показывает объекты и число операций, затем требует интерактивное подтверждение **Y/N**. Только `Y` разрешает работу. `N`, пустой ввод и EOF отменяют пакет до запуска задач. Перенаправленный stdin не подходит; флага обхода подтверждения нет.

- Несколько селекторов образуют все сочетания. `allow '*' '*'` разрешает каждому активному клиенту каждый зарегистрированный VPN-сервер. `--servers '*'` создаёт одного клиента с этим списком, без подписки на будущие узлы.
- Общие селекторы включают действующих участников, в том числе временно недоступных. Исключённые узлы/отозванные клиенты пропускаются. Управление VPN-серверами выбирает зарегистрированные VPN-узлы; `vpn status '*'` и `vpn server install '*'` — Linux-узлы.
- `node kick '*'`, `node remove '*'` и `node routes '*'` исключают текущий узел. `node accept '*'` / `reject '*'` выбирают ожидающие заявки. При перезагрузке текущий узел обрабатывается последним, с общим подтверждением Y/N.
- Состав фиксируется до подтверждения. Задачи и вывод последовательны; ошибки отображаются, остальные задачи продолжаются. Любая ошибка даёт ненулевой код завершения.
- `node list` и `vpn client get` **не принимают** `*`. Для списка используется `node list [--interactive]`, для выгрузки — один клиент. **`--interactive` нельзя сочетать с селектором**, в том числе в `pnt sh`.
- Пробросы принимают `--listen '*:8080'`, `--to '*:80'` и `--via '*'`, только если итоговые правила имеют разные входные порты. Конфликты отклоняются до создания правил.

Имена клиентов должны оставаться уникальными: `vpn client rename '*' NewName` отклоняется, если выбрано несколько клиентов.

Селекторы действуют в аргументах выбора существующего узла/клиента. Они не разворачивают текст команд, новые имена, ключи, пути файлов, внешние адреса, IP нового узла, SSH-адрес установки и ID приглашений, правил или ассетов Cesium.

## AmneziaWG и VPN-клиенты

```sh
pnt vpn server install <node>
pnt vpn server list
pnt vpn server rename <node> 'Нидерланды #1'
pnt vpn server status <node>
pnt vpn start [node]
pnt vpn stop [node]
pnt vpn restart [node]
pnt vpn server remove <node>

pnt vpn client create alice --servers vpn-1,vpn-2 --out=alice.pnt
pnt vpn client list
pnt vpn client rename alice NewName
pnt vpn client show alice
pnt vpn client get alice
pnt vpn client get alice --out=alice-copy.pnt
pnt vpn client allow alice vpn-2
pnt vpn client deny alice vpn-2
pnt vpn client handshake alice [node]
pnt vpn client unbind <client-id>
pnt vpn client revoke alice
```

`pnt vpn server status <node>` показывает текущее состояние интерфейсов/клиентов и накопительную статистику: всего и активных наблюдаемых сеансов, прямые/транспортные подключения, показатели по клиентам и принятые/отправленные сервером байты, маршруты с ID узлов, использование каждого узла для входа и транзита. Выходной узел опрашивает AmneziaWG каждые 15 секунд и сохраняет историю в своей SQLite-базе; отчёт доступен через маршруты кластера. Для начала сбора обновите выходные узлы. История не реплицируется на другие узлы и доступна при остановленном VPN.

Это наблюдаемые сеансы, а не TCP-соединения или число рукопожатий. Повторные рукопожатия, резервные реле и смена маршрута не создают лишних логических подключений. Обнаруженное отключение или перерыв наблюдений более 180 секунд начинает новый сеанс при следующем подключении. Краткие отключения между опросами могут быть пропущены, а прямое отключение определяется с задержкой до таймаута рукопожатия. Один сеанс может использовать несколько способов/маршрутов, поэтому их счётчики могут пересекаться. Первые счётчики устанавливают начальный уровень: прошлый трафик не восстанавливается. Последующие сбросы счётчиков учитываются без повторного подсчёта. Байты измеряются на выходном сервере; распределение по способам/маршрутам между опросами приблизительное. При прямом VPN трафик идёт мимо кластера, поэтому узлы управления/выдачи каталога не считаются реле данных. История переживает перезапуск PNT; для её восстановления нужна резервная копия базы выходного узла.

PNT устанавливает AmneziaWG на Debian или подключает существующую нативную/Docker-конфигурацию, предлагает выбор и настраивает forwarding/брандмауэр. Нативный поиск включает `/etc/amnezia/amneziawg`, `/etc/amneziawg` и `/opt/amnezia/awg`. Поддерживается только **AmneziaWG**; обычный WireGuard и `/etc/wireguard` не используются. Неуправляемые PNT пиры сохраняются.

Импортируйте `.pnt` в [PNT VPN](https://github.com/spark108/amnezia-pnt). Клиенты не управляют кластером, не входят в топологию узлов и не передают транзитный трафик. Изменение прав не требует повторного импорта.

Первое подключение привязывает новый профиль к отдельному ключу Android Keystore / Windows CNG, которого нет в `.pnt`. После этого копия файла отклоняется на другом устройстве. `unbind` сбрасывает привязку, отзывает поколение сессии и удаляет VPN-ключи на доступных серверах; удаление на отключённых ожидает связи. Профиль может занять следующее устройство, включая прежнее. `revoke` окончательно запрещает идентичность.

Узел, создавший клиента, последовательно принимает решения о привязке и должен быть доступен при авторизации; автоматического переноса управления нет. Для клиентов, созданных до привязки, выполните `unbind` один раз, назначив управляющий узел и отозвав старые сессии. Сохраняйте резервную копию его базы.

Профили содержат закрытые учётные данные. Повторная выгрузка сохраняет идентичность и обновляет список серверов. Новые ключи хранятся в зашифрованном виде в синхронизируемом реестре; для старых профилей, созданных до хранения ключей, нужен исходный `.pnt`. Существующие файлы не перезаписываются. Состояние подключения определяется по рукопожатиям AmneziaWG и может измениться с задержкой.

## Пробросы и веб-интерфейс

```sh
pnt forward add --listen edge-1:8080 --to exit-1:80
pnt forward add --listen edge-1:8443 --via exit-1 --to 192.0.2.50:443
pnt forward list
pnt forward show <id>
pnt forward remove <id>
pnt web enable
pnt web disable
```

TCP-потоки идут по маршрутам PNT к узлу или внешнему IP, доступному с выхода. В веб-интерфейсе также выбираются адреса/интерфейсы входа и выхода. UDP-пробросы и универсальная L3-сеть не реализованы.

`web enable` запрашивает пароль и синхронизирует настройку. Адрес — `https://<node-ip>:8016/`, логин `admin`; отключение сбрасывает пароль. Используется сгенерированный сертификат. Полноэкранный глобус показывает геолокацию узлов, прямые связи/задержки, VPN-метки и маршруты. Координаты можно задать вручную. Управление находится в скрывающейся панели, меню переименования/свойств узла и странице пробросов.

```sh
pnt cesium token
pnt cesium add <asset-id> [name]
pnt cesium list
pnt cesium enable <asset-id>
pnt cesium disable <asset-id>
pnt cesium remove <asset-id>
pnt cesium status
```

Учётные данные Cesium ion вводятся через CLI; `pnt cesium token clear` удаляет их. Поддерживаются подложки, рельеф, совместимые дополнительные слои и освещение дня/ночи.

На линиях рядом с пингом показана текущая суммарная скорость трафика PNT в обе стороны (Mbps). Измерения выполняются примерно раз в пять секунд и распространяются по кластеру. Это не тест пропускной способности; накладные расходы IP/TLS/QUIC не учитываются. Для устаревших или отсутствующих данных показывается `—`.

## Доступ к файлам кластера через FTPS

```sh
pnt ftp enable
pnt ftp status
pnt ftp disable
```

Включение и отключение распространяются по кластеру, включая новые узлы. Недоступные участники применяют настройку после синхронизации. Шлюз работает внутри службы PNT, отдельный FTP-сервер не требуется. Перед включением обновите все участвующие узлы.

Параметры FileZilla или WinSCP для подключения к любому доступному шлюзу:

| Настройка | Значение |
| --- | --- |
| Протокол | FTP с обязательным **явным TLS** — FTPS, не SFTP и не неявный TLS |
| Порт управления | **440/TCP** |
| Логин | `admin` |
| Пароль | Исходный общий ключ кластера |
| Передача | Пассивная, защищённая TLS (`PROT P`), двоичный режим |
| Пассивные порты | **44100–44131/TCP** |

Спецификации протокола: [FTP через TLS (RFC 4217)](https://www.rfc-editor.org/rfc/rfc4217), [MLSD и REST (RFC 3659)](https://www.rfc-editor.org/rfc/rfc3659).

Сертификат узла самоподписанный. Перед доверием сверьте SHA-256 с `pnt ftp status` на выбранном шлюзе. Выберите двоичный режим: преобразование текстовых файлов ASCII не поддерживается. Вход без TLS, незащищённые соединения данных и активный FTP отклоняются. Служба открывает/закрывает правила брандмауэра, но внешние межсетевые экраны также должны разрешать эти порты. Для шлюза за NAT пробросьте те же порты и используйте EPSV: адрес берётся из управляющего соединения. Внешняя точка входа должна быть доступна клиенту; конечные узлы могут оставаться за NAT.

В корне отображаются каталоги `Имя узла [node-id]`. На Linux внутри доступен корень файловой системы, на Windows — диски `C`, `D` и т. д. Активные пути привязаны к ID узла. Недоступные узлы видны в списке, открытие возвращает ошибку доступности. Виртуальные каталоги узлов нельзя создавать/удалять. Файловые операции выполняются с правами службы конечного узла — обычно root/LocalSystem. Отдельных пользователей и ограничений каталогов нет.

Поддерживаются просмотр каталогов, свойства файлов, скачивание, загрузка, создание и нерекурсивное удаление каталогов, удаление файлов, переименование внутри узла. Запросы идут по маршрутам PNT, включая реле и обратные каналы NAT. Файлы передаются блоками до 1 МиБ с SHA-256; при обрыве транспортная операция повторяется через маршрутизацию до двух раз. Загрузка идёт в закрытый временный файл рядом с назначением и подменяет его после итоговой проверки. Если назначение изменилось параллельно, подмена отклоняется. Новые файлы Linux получают режим `0600`, при замене сохраняются Unix-биты доступа. Владелец файла и ACL Windows определяются службой/временным файлом, а не исходным файлом. Метаданные файловой системы через FTP не копируются.

`REST` позволяет продолжить скачивание и загрузку относительно существующего файла назначения. Изменение версии источника во время одной передачи отклоняется. Незавершённая загрузка не продолжается из другого FTP-сеанса: после переподключения её нужно начать заново либо явно продолжить существующий готовый файл. Временные файлы и подтверждения удаляются через 24 часа. Если остановился сам шлюз, подключитесь к другому доступному узлу. Перемещение между узлами, рекурсивное удаление и FTP-расширения смены прав не поддерживаются.

## Доступ, порты и данные

| Порт | Назначение |
| --- | --- |
| UDP 442 | Основной постоянный QUIC-транспорт с закреплёнными сертификатами; на Linux нужен libmsquic |
| TCP 442 | Резервный TLS-транспорт, совместимость, вступление и вход VPN-клиентов |
| TCP 8016 | HTTPS-панель, если включена |
| TCP 440, 44100–44131 | FTPS: управление и защищённая пассивная передача при включении |
| Настроенный UDP-порт AmneziaWG | Прямое VPN-подключение к выходу |
| TCP 22 | Удалённая установка по SSH, где применимо |

VPN-датаграммы сохраняют границы в потоках PNT. Между узлами используются надёжные потоки QUIC, а не QUIC DATAGRAM; вход клиента работает через TLS/TCP. Резервные реле и heartbeat восстанавливают маршрут, сохраняя VPN-интерфейс/ключи. Возможна потеря пакетов; смена выхода не сохраняет его NAT-сессии.

CLI доступен root/группе `pnt` на Linux; на Windows — администратору с повышенными правами, LocalSystem или группе `PNTAdmin`. Установка создаёт группы, но не добавляет пользователей:

```sh
sudo usermod -aG pnt <user>
```

```powershell
Add-LocalGroupMember -Group PNTAdmin -Member '<user>'
```

После изменения членства войдите заново. Эти группы и участники кластера имеют полный административный доступ PNT, включая сертификаты и удалённые команды. Кворума и автоматической смены общего ключа при исключении нет. Отключённая часть сети может хранить старое членство до синхронизации.

| Платформа | Данные / журналы |
| --- | --- |
| Debian | `/var/lib/pnt`; `journalctl -u pnt.service`; конфигурация `/etc/default/pnt` |
| Windows | `%ProgramData%\PNT\data`; `service.log` там же; конфигурация `%ProgramData%\PNT\config` |

Сохраняйте базу, сертификат и состояние VPN вместе. Идентичности должны быть уникальны. Вступление и внешние пробросы используют IPv4. Пользовательской схеме nftables/iptables могут потребоваться собственные разрешающие правила.

## Справка и проверки

```sh
pnt --help
pnt vpn client allow --help
pnt help forward add
```

У каждой команды/группы отдельная справка. Сборка и проверки для разработки:

```sh
dotnet build -c Release
dotnet run --project tests/CliChecks -c Release
dotnet run --project tests/SelectorChecks -c Release
dotnet run --project tests/TerminalChecks -c Release
dotnet run --project tests/NodeChecks -c Release
dotnet run --project tests/RelayPolicyChecks -c Release
dotnet run --project tests/FtpChecks -c Release
dotnet run --project tests/VpnChecks -c Release
python3 tests/VpnChecks/adapter_checks.py
```

Проверки используют изолированные данные и не перезагружают реальные машины. Другие тесты находятся в `tests/`; некоторым нужны системные/сетевые привилегии.
